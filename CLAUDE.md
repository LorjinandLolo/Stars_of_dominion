# Stars of Dominion

Next.js 16 / React 19 / TypeScript. PostgreSQL via Prisma (`prisma/schema.prisma`, client generated into `lib/generated/prisma/`, singleton in `lib/db.ts`), better-auth for accounts (`lib/auth.ts`), Zustand state, Tailwind, Jest.

- Database: local dev runs on the native PostgreSQL 18 service on port 5432 (role `stars`, db `stars_dominion`, set in `.env.local`); Docker Desktop was dropped from local dev on 2026-09-14 because it kept dying under memory pressure. `docker compose up -d` (Postgres 17 on 5433) still works as an alternative; the home server uses `compose.prod.yaml`. Migrations: `npm run db:migrate`. Worker: `npm run worker:forever` restarts it when the hang watchdog exits.
- Dev server: `npm run dev`. Game loop worker: `npm run worker` (scripts/game-loop.ts) — required for the live game.
- Bootstrap a fresh DB: `npx tsx scripts/push-init-state.ts` (world snapshot) then `npm run setup:duel` (dev accounts + faction claims).
- Client gets game state by polling `/api/game/sync` (hooks/useGameSync.ts); JSON-bearing DB columns are TEXT holding JSON strings — call sites JSON.parse/stringify.
- Narrative (`lib/narrative/`, all five phases landed — design in `docs/narrative-system/README.md`): `chronicle.ts` records what actually happened (`ChronicleEvent`, append-only, real actor in `actorIds`, public knowledge ceiling in `attribution`); call sites use `chronicle.record(world, draft)`. It must NOT import `lib/db` — emission sites live in services the client bundles, so the write lives in `chronicle-flush.ts`, which the game loop calls once per cycle AFTER the snapshot commits. `scripts/narrator.ts` (`npm run narrator`, own container) turns events into articles: `memory-service.ts` derives feuds and precedent by query, `press-voices.ts` picks which outlet covers a story, `prose/` writes it (template always works; `NARRATOR_LLM=ollama|gemini` degrades to it on any failure), `retrospective-service.ts` names closed eras. The narrator only ever READS what the simulation writes — its write set is `NarrativeArticle`, `Gazette`, `Feud`, `narratedAt`.
- AI empires act through the player's order handlers: deciders in `lib/ai/` call `queueAIOrder(world, {factionId, actionId, payload, onDone?})` (`lib/ai/ai-orders.ts`), and the worker drains the outbox into `executeOrder` every loop and right after the strategic tick (the soak harness drains too). Only AI-run factions can queue. New AI behaviour should queue an order, not call the service directly; older AI code (fleet building, colonization, construction, research) still calls services directly and is the remaining parity work. `lib/ai/state-desk-ai.ts` holds counter-intel, press defence, staffing, secession and POW decisions; probe `npx tsx scripts/ai-parity-probe.ts`. `lib/ai/offence-ai.ts` is the offensive toolkit (press campaigns and crisis stances, envoys/rumours/gambits/tribute/promises/breakaway meddling, marques and covert pirate sponsorship, bounties, company subsidies and host policy, Banking Clan loans, Sarrak/Gabagoon/Buthari rites, agent roster); its `order()` checks the tech gate and the political-capital price (`lib/actions/political-costs.ts`, the table executeOrder charges) before queuing; probe `npx tsx scripts/ai-offence-probe.ts`.
- Espionage lives entirely in `lib/espionage/` (op catalog, per-faction intel state, agents, networks); all mutations go through the order queue (`ESP_*` actions handled in scripts/game-loop.ts), reads come from the synced world via `espionageState` in the UI store. There is no separate "intelligence" system — it was consolidated in July 2026.
- Ship design (`lib/combat/ship-registry.ts` + `ship-design-service.ts`, doc in `docs/ship-design/README.md`): a design = hull + modules; `summarizeDesign` is the ONE pricing/validation function (designer UI and worker both call it). Fleet `composition` keys are lowercase ship classes (`corvette`..`battleship`); `normalizeComposition` folds legacy UPPERCASE on load. Every recruit order resolves through `resolveRecruitSpec` (unknown unit types are refused, not free). Designs live in the owner's faction shard, never the shared snapshot.
- Ground combat (`lib/combat/siege/`, probe `npx tsx scripts/ground-war-probe.ts`): a siege with `districts.formations` is POSITIONAL — the formations are the truth and the army pools (`unitComposition`, `garrisonTroops`, `totalLandedTroops`, morale/supply/cohesion) are rewritten from them every cycle by `processSieges`. Anything that adds men to a pool between cycles (garrison recruits, turned prisoners, disembarked armies) is seeded as new formations at the next cycle by `seedArrivals`; anything that kills men on the board between cycles (orbital fire) must ALSO deduct from the pool or it comes back as a phantom recruit. Field armies stationed on a world are absorbed into the siege (`absorbStationedArmies`). `orbitalSupportPower` is recomputed every tick from fleets actually in orbit. Stances persist across cycles; stance reads are one-shot and scored into `siege.reads`. Organisation is a combat quantity: formations at or below `BREAK_ORG` retreat to friendly ground or surrender (prisoners to the last man) if cut off. `GroundSiegeEngine`'s pool-based path only runs for legacy sieges without formations. Pacing lives in `siege-pacing.ts` (one cycle = 60 ticks = 5 real minutes; probes set `pacing.cycleLengthTicks = 4` and assert in cycles; per-tick bombardment is scaled by `bombardTickScale` so per-cycle damage is pacing-independent). The sky decides the ground: `orbit-state.ts` (`siege.orbit`, recomputed every tick) feeds supply (beachhead starves after `BLOCKADE_GRACE_CYCLES` without the orbit, formations surrender after `STARVE_SURRENDER_CYCLES`), landings (`canCrossOrbit` gates embark/disembark/reinforce) and bombardment. Strongpoints (`strongpoints.ts`, cached on `war.strongpoints` each cycle from `computeSectorOccupancy` + chokepoints + capital) have live effects only while held and active: shield blocks orbital fire and lets the defender land, barracks/fortress feed the militia levy and are where recruits muster, fortress/chokepoint/capital raise entrenchment caps; shield and fortress fall to sappers after `SAPPER_CYCLES`, never to the capture-ruin roll. The capital falls only after `CAPITAL_FALL_CYCLES` held (or no defender left). A defender with no orders runs `defence-doctrine.ts` (`war.defenderAuto`, cleared by their first order); the AI defender runs the same. Siege news goes through `siege-events.ts` (notifications to both sides + chronicle). `capturePlanet` hands survivors to the winner as the new garrison (`garrison.ts`).
